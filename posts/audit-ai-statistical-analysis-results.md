AI 很容易產生一段看起來專業的統計解釋：它會寫出檢定名稱、p 值、效果量，甚至 APA 格式。但「格式完整」和「分析正確」是兩件不同的事。

> **先說結論**：不要問「這個 AI 統計答案看起來合理嗎？」而要逐層檢查研究問題、資料結構、方法、實際輸出與文字結論是否一致。

## 為什麼 AI 的統計答案需要查核？

Ruta 等人（2025）讓 ChatGPT 執行單變量統計，發現描述統計表現良好，但推論統計的正確率會隨提示完整度改變：基本提示為 32.5%，中等提示為 81.3%，進階提示為 92.5%。這表示同一個工具可能因為研究者少說了一項設計資訊，就得到不同品質的答案。

另一項使用 20 個標準化情境比較六種 LLM 的研究發現，各模型都能選對檢定，但複雜統計推理的說明品質仍有差異（Shukla et al., 2025）。這兩項結果並不矛盾：選對檢定名稱，不代表資料處理、模型規格、假設診斷與解釋都正確。

## 五層查核法

### 第一層：問題有沒有說清楚？

先確認：

- 想比較、預測，還是估計關聯？
- 主要結果是哪一個？
- 分析單位是參與者、trial，還是時間區段？
- 資料是獨立、配對，還是重複量測？
- 哪些分析是事前假設，哪些是探索？

如果這些資訊沒有提供，AI 選出的檢定只能建立在猜測上。

### 第二層：資料有沒有被讀對？

檢查最基本但常被忽略的問題：

```text
資料列數是否正確？
每位參與者有幾列？
單位是秒還是毫秒？
缺失值是否被誤當成 0？
組別標籤有沒有顛倒？
pre/post 是否依正確時間排序？
```

例如反應時間原始值是秒，AI 卻當成毫秒，程式仍能順利完成，但整篇結果會錯 1000 倍。

### 第三層：方法是否符合研究設計？

不要只看 AI 有沒有寫「先檢查常態性」。還要確認：

- 配對資料是否使用配對或重複量測方法。
- trial-level 資料是否忽略參與者內相關。
- 二元結果是否誤用一般線性模型。
- 共變項是否在結果發生之後才產生。
- 多個結果與比較是否處理 multiplicity。
- 樣本數是否足以支持複雜模型。

### 第四層：數字能否由程式重新算出？

我會要求 AI 同時交付：

- 完整程式，而不是只有結果句子。
- 套件與版本。
- 分析樣本數及排除筆數。
- 描述統計與主要模型輸出。
- 模型診斷與警告訊息。
- 固定隨機種子（如果方法需要）。

再用另一段獨立程式或可信統計軟體抽查關鍵數字。不是叫第二個 AI 重新描述第一個 AI 的答案，而是重新計算。

### 第五層：文字有沒有說過頭？

常見錯誤包括：

| AI 可能寫的句子 | 問題 | 較適當寫法 |
|---|---|---|
| p > .05，兩組沒有差異 | 不顯著不等於相等 | 未觀察到明確差異，估計仍有多少不確定性 |
| p < .05，運動改善認知 | 觀察性關聯被寫成因果 | 較高活動量與較佳表現相關 |
| HRV 較高代表副交感神經更健康 | 生理解釋過度簡化 | 在特定量測條件下，該指標與迷走調節相關 |
| 結果具有臨床意義 | 未定義重要效果門檻 | 效果大小為多少，是否達預定門檻尚待評估 |

Wasserstein 與 Lazar（2016）指出，科學結論不應只根據 p 值是否跨過門檻。效果量、信賴區間、設計品質與先驗證據都必須一起解讀。

## 引用也要查核

統計說明常會附上看似正式的論文。Walters 與 Wilder（2023）檢查 636 筆 AI 生成引用，發現早期 GPT-3.5 與 GPT-4 都存在捏造與書目錯誤。模型版本已持續更新，這些比例不能直接套用到今天，但「逐一確認 DOI、全文與支持關係」仍是必要做法。

## 帶走三個重點

1. AI 答案的正確率高度依賴你是否提供完整研究設計。
2. 第二個 AI 的同意不是驗證；重新計算和查看診斷才是。
3. 統計結果必須同時報告效果、區間、樣本、假設與限制。

> **一句話總結**：AI 可以加速統計工作，但只有能從原始資料重新計算、通過設計與診斷檢查的結果，才值得寫進研究報告。

<!-- PROFESSIONAL -->

AI 統計輸出的稽核應採用 fail-closed 原則：在資料結構、estimand、程式、診斷或書目證據不完整時，狀態是「尚未驗證」，不是「看起來合理」。語言模型的流暢度不能作為統計正確性的代理指標。

> **證據定位**：現有研究多使用特定模型、提示與標準化任務，結果不能當成所有版本的固定準確率。它們支持的是建立結構化驗證流程，而不是宣稱某模型永遠可靠或不可靠。

## Gate 1：研究設計與 estimand audit

在執行任何程式前，先凍結以下 contract：

```yaml
design: repeated_measures
unit_of_analysis: participant
outcome: median_rt_ms
timepoints: [pre, post]
primary_contrast: post_minus_pre
grouping: exercise_vs_control
covariates: [baseline_value]
missing_data: defined_in_protocol
multiplicity: primary_outcome_only
```

稽核問題：

- 暴露、結果與共變項的時間順序是否支持欲解釋的方向？
- repeated measures 是否被誤當 independent samples？
- multiple trials 是否造成 pseudoreplication？
- outcome 是連續、計數、比例、序位或 time-to-event？
- 主要 contrast 是否在看過結果前確定？

如果 contract 無法完成，AI 只能提出候選方案，不應輸出正式 p 值。

## Gate 2：data integrity audit

建立 machine-checkable assertions：

```python
assert df['participant_id'].notna().all()
assert df.groupby('participant_id')['phase'].nunique().le(2).all()
assert df['rt_ms'].between(100, 3000).all()
assert set(df['group'].dropna().unique()) <= {'exercise', 'control'}
```

但 assertion 閾值必須來自 protocol 或領域知識，不能讓 AI 因「常見做法」自行決定。稽核紀錄應包含：

- import row count 與 unique IDs。
- join 前後 row count。
- missingness by variable/group/time。
- exclusion flow 與 reason code。
- unit conversions。
- duplicate resolution。
- checksum 或 data version。

## Gate 3：analysis-code audit

### 方法對應

確認程式實際執行的模型與文字描述一致。例如文章寫 mixed-effects model，但程式最後可能只保留 participant mean 後跑 t test。稽核要查看 function call、formula、reference level、contrast coding 與 options。

### 套件預設值

不同軟體可能在以下方面使用不同預設：

- Type I/II/III sums of squares。
- treatment/sum coding。
- equal-variance 或 Welch t test。
- missing rows 的處理。
- degrees-of-freedom approximation。
- multiple-comparison correction。
- confidence interval method。

因此「R、Python 與 SPSS 都跑完」不保證分析等價，必須比較 estimand 與設定。

### 重算而非重述

至少選擇一種獨立驗證：

1. 用不同實作重算關鍵估計值。
2. 用小型手算或模擬資料驗證方向與尺度。
3. 對資料列順序、組別標籤與單位做故意擾動，確認測試能抓到錯誤。
4. 將模型結果與原始描述統計做 sanity check。

讓第二個 LLM 閱讀第一個 LLM 的結論只能算 review suggestion，不是 computational verification。

## Gate 4：assumption and diagnostic audit

| Model family | Minimum checks |
|---|---|
| t test/ANOVA | independence、distribution of residuals、variance structure、influence |
| linear regression | functional form、residuals、heteroskedasticity、influence、collinearity |
| logistic regression | separation、calibration、linearity in logit、events per parameter |
| mixed model | grouping structure、random effects、singularity、convergence、residuals |
| repeated HRV windows | nonstationarity、within-person dependence、artifact burden、window length |

診斷不應退化成「Shapiro–Wilk p > .05 才能分析」。大樣本下微小偏離容易顯著，小樣本又缺乏偵測力；應結合圖形、模型對偏離的穩健性與敏感度分析。

## Gate 5：statistical interpretation audit

Greenland 等人（2016）整理多種常見誤解，包括把 p 值當成虛無假設為真的機率、把不顯著當成無效果、把信賴區間解讀為固定參數的直接機率範圍。稽核時逐句標記：

- **descriptive**：樣本中觀察到什麼？
- **inferential**：模型估計與不確定性是什麼？
- **causal**：設計是否支持因果？
- **clinical/practical**：是否有預先定義的重要門檻？
- **generalization**：樣本可外推到哪些族群？

最低報告單位應為：estimate、interval、unit、analysis N、model 與 context。p 值只是一部分。

## Gate 6：sample size 與 multiplicity

Lakens（2022）主張樣本數需要可辯護的目標。AI 稽核不應在研究完成後只計算 observed post hoc power，而應檢查：

- 原先樣本數依據與主要 estimand 是否一致。
- 最終有效樣本是否因排除大幅下降。
- 信賴區間是否足以排除具實務重要性的效果。
- 多結果、多時間點與多模型是否增加選擇彈性。
- sensitivity analysis 是否被誤當多次尋找顯著。

## Gate 7：LLM-specific audit

Ruta 等人（2025）使用單變量分析任務發現，推論統計正確率隨提示從基本到進階而大幅提升。這支持一個重要觀念：prompt 應被視為 analysis specification 的一部分並版本化。但該研究限於特定工具、資料與方法，不能推論「進階提示能讓所有分析達到 92.5%」。

Shukla 等人（2025）的 20 個標準化情境中，六種 LLM 都選對檢定，但複雜方法的 reasoning quality 較不一致。這提醒我們：benchmark 的 test-selection accuracy 不能替代真實資料的 preprocessing、diagnostics 與 interpretation audit。

StatLLM（Song et al., 2026）建立涵蓋資料視覺化、描述統計、檢定、regression、ANOVA、GLM、生存分析與模型選擇的評估資料集。這類 benchmark 的價值在於使統計能力可被系統測量；對個別研究而言，仍需以自己的資料與預先定義答案建立 local validation cases。

## Gate 8：citation audit

Walters 與 Wilder（2023）發現，早期 GPT-3.5/4 生成的 636 筆引用中存在捏造與實質書目錯誤。版本更新會改變錯誤率，因此文章不把其比例當成現行模型估計；但以下流程不應省略：

```text
citation text
  → DOI/PMID resolves?
  → authors/title/year match?
  → full text accessible?
  → study design and population match claim?
  → exact result/limitation supports wording?
```

只確認 DOI 存在仍不足，因為真實 DOI 也可能被錯配到不支持該句話的研究。

## 發布前 15 項 checklist

1. 問題、estimand 與模型一致。
2. analysis unit 正確。
3. 原始資料未被覆寫。
4. join、缺失與排除有紀錄。
5. 單位與類別 reference level 正確。
6. 程式完整且可重跑。
7. 套件版本與 seed 已保存。
8. 描述統計能支持模型結果的尺度與方向。
9. 假設與診斷已檢查。
10. convergence warning 未被忽略。
11. estimate、interval 與 p 值一致。
12. multiplicity 與 sensitivity 有交代。
13. 不顯著未被寫成相等。
14. 觀察性結果未被寫成因果。
15. 每筆引用的 DOI 與全文支持已核對。
