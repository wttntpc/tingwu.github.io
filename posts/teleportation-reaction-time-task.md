看到畫面出現目標後，我們「開始動」和「完成動作」其實不是同一件事。瞬間移動作業用一個很簡單的點擊遊戲，把這兩段時間分開記錄。

## 作業怎麼進行？

受試者先用手指按住紅色方塊。等待一段不固定的時間後，藍色方塊會出現在另一個位置；受試者要立刻放開紅色方塊，再點擊藍色方塊。

等待時間與方塊位置採隨機方式，目的在減少受試者預先猜測目標何時、在哪裡出現。

## 兩個時間代表不同歷程

- **反應時間（RT）**：從藍色方塊出現，到手指離開紅色方塊。
- **移動時間（MT）**：從手指離開紅色方塊，到點擊藍色方塊。

RT 比較接近「看到刺激後多久開始行動」，MT 則反映「動作花了多久完成」。如果只把兩者加在一起，我們就很難知道變慢發生在資訊處理，還是動作執行。

## 很快不一定代表表現好

過快的反應可能是提前猜測，過慢則可能來自分心、動作中斷或設備問題。分析前應先訂定資料品質規則，保留被排除的紀錄與理由，不能看到結果後才調整門檻。

前後測也應呈現每個人的變化。有些人的 RT 變快、MT 不變；另一些人可能相反。只看群體平均值，容易錯過這些重要差異。

> 一個看似簡單的點擊作業，真正的價值在於把「決定開始動」與「把動作完成」拆開觀察。

瞬間移動作業是一種簡單反應時間典範。受試者持續按住起始刺激，經隨機等待後出現單一目標，再放開起始位置並點擊目標。單一刺激—單一反應的設計降低反應選擇負荷，使測量較集中於刺激辨識、動作啟動與動作執行。

## 操作定義與測量構念

資訊處理可概念化為刺激辨識、反應選擇與反應程序化三個階段。此作業將輸出拆成：

| 指標 | 操作定義 | 主要解讀 |
|---|---|---|
| Reaction Time（RT） | 目標出現至手指離開起始位置 | 刺激辨識、注意與動作啟動 |
| Movement Time（MT） | 離開起始位置至接觸目標 | 動作執行速度與控制 |

RT 與 MT 應分開保存與分析。將兩者合併為總完成時間，會混淆認知啟動與實際動作階段。

## 從 session JSON 轉成試驗層級資料

原始資料常以每次 session 一列、試驗紀錄存放於 JSON 陣列。分析前需展開為 long format，使每列代表一個 trial，至少包含匿名受試者代碼、phase、round、RT 與 MT。

```python
rows = []
for _, session in sessions.iterrows():
    for trial in json.loads(session["records"]):
        rows.append({
            "participant": session["participant"],
            "phase": session["phase"],
            "round": trial["Round"],
            "rt_ms": trial["ReactionTime"] * 1000,
            "mt_ms": trial["MovementTime"] * 1000,
        })
trials = pd.DataFrame(rows)
```

單位轉換是常見錯誤來源：若 JSON 使用秒，輸出時必須明確轉為毫秒，欄位名稱也應標示 `_ms`。

## 品質控制要先於結果比較

範例 Pipeline 將小於 100 ms 或大於 1000 ms 的 RT／MT 標示為可疑值，但門檻應依裝置特性、任務設計、先驗文獻與研究計畫預先決定，不能視為跨研究通則。

QC 表應保留缺值、過快、過慢及排除比例。異常值檔案不應只被刪除，而應能回到受試者、session 與 trial 層級查核可能原因。

## 前後測分析的層級

試驗層級資料不是彼此獨立的受試者。可先依受試者 × phase 摘要 RT／MT，再進行配對比較；若希望保留 trial 層級資訊，則應採能處理受試者內相依性的混合效果模型。

配對 t 檢定的常態性假設應檢查每位受試者的前後差值，而非分別檢查 pre 與 post。Wilcoxon 符號等級檢定可作為不依賴常態假設的對照，但方法選擇不能只由一個 p 值自動決定。

視覺化建議同時包含分布圖與個體配對線，呈現資料範圍、異常試驗及每位受試者的變化方向。若某組樣本不足，應限制為描述性呈現，不能以單組前後差異推論組間介入效果。
