拿到研究資料時，第一個問題通常不是「要用哪個統計檢定」，而是：**每一欄到底代表什麼？每一列又代表誰、哪一次測量？**

如果這一步沒有說清楚，再進階的統計方法也可能分析錯對象。資料整理的目的不是把試算表變漂亮，而是讓資料的意義、單位和測量結構可以被人與程式正確理解。

> 本文是「數據整理與統計分析」系列第 1 篇。核心原則：先定義變項，再整理表格；先保留原始資料，再建立可分析版本。

## 先區分：資料型態不只一種分類

研究者常把幾個不同概念混在一起：

- **儲存型態**：文字、整數、小數、日期或布林值。
- **測量尺度**：名目、順序、等距或等比尺度。
- **數值特性**：離散或連續。
- **研究角色**：結果變項、解釋變項、共變項或識別欄位。

例如「組別」在檔案裡可能用 `0`、`1` 儲存，但它仍是名目類別；數字只是編碼，不代表兩組之間可以做加減乘除。

| 測量尺度 | 可以回答的問題 | 研究範例 |
|---|---|---|
| 名目 | 是否屬於同一類？ | 實驗組／控制組、裝置型號 |
| 順序 | 哪一個較高？ | 疼痛等級、Likert 題目 |
| 等距 | 差多少？ | 某些標準化分數、攝氏溫度 |
| 等比 | 差多少、是幾倍？ | 年齡、反應時間、VO₂peak |

這套四尺度分類來自 Stevens（1946），適合用來思考「數值能做哪些有意義的運算」，但不能只看尺度名稱就自動決定統計方法。研究設計、資料分布、重複測量與模型目的也同樣重要。

## 一列應該代表一個觀察

Wickham（2014）把適合分析的 tidy data 濃縮成三條原則：

1. 每一個變項放在一欄。
2. 每一個觀察放在一列。
3. 每一類觀察單位放在一張表。

以下是虛構的運動研究資料：

| participant_id | group | time | vo2peak | rmssd_ms |
|---|---|---|---:|---:|
| P001 | exercise | pre | 31.2 | 36.4 |
| P001 | exercise | post | 34.7 | 41.8 |
| P002 | control | pre | 29.5 | 33.1 |

這種「長格式」讓每一列代表一位受試者在一個時間點的觀察，適合重複量測圖表與混合模型。寬格式不是永遠錯誤，但應依分析目的轉換，而且轉換過程需要留下程式與紀錄。

## 資料字典比欄位名稱更重要

只寫 `HRV`、`score` 或 `time` 不夠清楚。一份可使用的資料字典至少應記錄：

| 欄位 | 定義 | 單位／編碼 | 合理範圍 | 缺失值 |
|---|---|---|---|---|
| participant_id | 去識別化受試者代碼 | P001… | 不可重複 | 不允許 |
| group | 隨機分派組別 | exercise／control | 指定類別 | 不允許 |
| vo2peak | 心肺適能峰值 | mL·kg⁻¹·min⁻¹ | 依研究族群設定 | 空白 |
| rmssd_ms | 清理後 BBI 計算的 RMSSD | ms | 依量測流程設定 | 空白 |

「合理範圍」是品質檢查門檻，不是看到超出範圍就直接刪除。超出範圍可能是輸入錯誤、單位錯誤、設備問題，也可能是真實但少見的觀察，必須回到來源判斷。

## 缺失不是零，也不應用神祕代碼

`0`、空白、`NA`、`999` 可能代表完全不同的事情。若 `999` 被當成真實心率，平均數和圖表都會失真。建議：

- 原始資料保留原貌並設為唯讀。
- 分析資料使用一致的缺失表示方式。
- 另設欄位記錄缺失原因，例如設備失敗、退出研究或未施測。
- 不因為軟體不接受空白，就任意把缺失補成平均數或零。

## 一份可以直接使用的整理清單

1. 每個受試者是否有穩定且去識別化的 ID？
2. 每一欄是否只有一種定義與單位？
3. 類別編碼是否在資料字典中完整說明？
4. 每一列代表的觀察單位是否一致？
5. 重複量測是否有受試者 ID 與時間欄位？
6. 缺失、未施測與真正的零是否可以區分？
7. 原始檔是否保持唯讀，所有清理能否由程式重現？

研究資料的可分析性取決於三個彼此相關但不相同的層次：測量概念、資料結構與分析模型。把欄位存成 numeric 並不會自動使它成為連續變項；同樣地，把 Likert 題目標為 ordinal，也不能單獨決定最終模型。專業整理流程應先建立資料生成過程與變項定義，再設計機器可讀的資料結構。

## 測量尺度、數值特性與模型角色

Stevens（1946）提出名目、順序、等距與等比尺度，核心在於不同轉換下哪些關係仍保持不變。這個分類提供有用的測量起點，但現代分析不宜把它簡化成「名目只能做某檢定、連續只能做另一檢定」的決策表。

選擇分析方法時至少還要考慮：

- 結果變項的條件分布與連結函數；
- 觀察是否獨立、配對、巢狀或重複；
- 研究目標是描述、估計、預測或因果推論；
- 測量誤差、天花板／地板效應與取值範圍；
- 預先指定的主要 estimand。

離散／連續是數值取值特性；名目／順序／等距／等比是測量關係；outcome／predictor／covariate 則是模型角色。三者應分開記錄。

## Tidy data 與觀察單位

Wickham（2014）將 tidy data 定義為每欄一個變項、每列一個觀察、每表一類觀察單位。真正困難的地方通常是「觀察」如何界定。例如運動介入研究可能同時存在：

- participant-level：年齡、組別與基線特徵；
- visit-level：前測、後測及追蹤測量；
- trial-level：每一認知作業試次的反應與正確性；
- beat-level：每一個 BBI 與品質旗標。

若把不同粒度硬塞在同一張表，participant-level 欄位會大量重複，trial-level 缺失也容易被誤當成 participant-level 缺失。較穩定的設計是分表保存，再用明確的鍵值連結。

## 建立資料契約

資料字典可以進一步轉成 validation schema。每個欄位至少記錄：

1. 穩定欄位名稱與顯示名稱；
2. 概念定義、單位與量測時間；
3. 儲存型態與允許類別；
4. 合理範圍與不可缺失條件；
5. 衍生公式與原始來源；
6. 違規時的處理方式。

以下 Python 範例只示範結構檢查，不代表任何特定研究的排除標準：

```python
required = {"participant_id", "group", "time", "vo2peak", "rmssd_ms"}
missing_columns = required.difference(df.columns)
assert not missing_columns, f"Missing columns: {missing_columns}"

assert df["participant_id"].notna().all()
assert df["group"].isin(["exercise", "control"]).all()
assert df["time"].isin(["pre", "post"]).all()

duplicate_keys = df.duplicated(["participant_id", "time"], keep=False)
review_rows = df.loc[duplicate_keys]
```

程式發現異常後應輸出待查核清單，而不是自動刪除。任何更正都應連回原始紀錄、處理決策與執行版本。

## 寬格式與長格式的選擇

寬格式把 `pre`、`post` 放在不同欄，適合部分配對計算與人工閱讀；長格式使用 `time` 欄表示測量時點，通常更適合視覺化、群組摘要與混合效果模型。轉換時必須檢查：

- 主鍵轉換後是否仍唯一；
- 測量時點是否遺失或重複；
- 單位與欄位名稱是否被錯配；
- 列數變化是否符合預期；
- round-trip 或抽樣核對是否能還原原意。

## 缺失與異常值需要語意

空值只能表示「目前沒有數值」，不能說明原因。若分析需要區分技術失敗、退出研究、拒答與結構性未施測，應另設 reason code。缺失機制與處理方法屬於後續分析決策，不能在資料整理階段以單一平均值填補掩蓋。

同理，range check 只是偵測器。研究者需回到儀器紀錄、量表規則或原始表單，將異常列分類成可更正錯誤、不可判定、排除或保留，並保存決策軌跡。

## 建議的輸出層次

```text
data/raw/          唯讀原始輸出
data/interim/      去識別、格式轉換與待查核資料
data/processed/    依鎖定規則產生的分析資料
metadata/          資料字典、單位、值標籤與排除規則
scripts/           匯入、驗證、清理與衍生程式
reports/qc/        缺失、重複、範圍與流程摘要
```

資料整理完成的標準不是「Excel 看起來整齊」，而是另一位研究者能從唯讀原始檔、資料字典和程式重建相同的分析資料。
